Instalar

Instale uma vez, use pelo id

Funciona em qualquer projeto Next.js da Jovens Gênios. Não precisa configurar nada no Next.

1

Baixe o kit e descompacte na raiz do projeto

Pelo link da página 2, ou pelo terminal. O .zip cria só components/planetas: os planetas não vêm nele, são lidos da web.

REPO=https://github.com/Jovens-Genios/Planetas-3D
curl -LO $REPO/releases/download/kit-planetas/kit-planetas.zip
unzip -o kit-planetas.zip -x LEIA-ME.txt && rm kit-planetas.zip
2

Instale o three.js

npm i three
npm i -D @types/three
3

Use onde o planeta aparece

Funciona dentro de Server Components (o componente já é 'use client'):

import { Planeta } from '@/components/planetas'

<Planeta id="planeta-emocoes" tamanho={240} alt="Planeta Emoções" />
✓

Pronto. Sem configurar nada, o componente busca o planeta na web pelo id, e ele:

  • desenha só o planeta, com fundo transparente, sobre o fundo que a tela já tiver;
  • gira sozinho, uma volta a cada 40 s, e pode ser girado com a mão e com as setas;
  • mostra o pôster na hora e troca pelo 3D quando carrega;
  • respeita “reduzir movimento” e fica só no pôster se não houver WebGL.

Se o projeto usa src/, mova components/planetas para src/components/planetas.

Planetas novos

Planeta novo? É só usar o id novo

O Design cria e publica o planeta na web. A engenharia não baixa nada nem atualiza o kit: o componente encontra o planeta novo pelo id.

DesignCria e prepara

Gera o planeta, reduz para menos de 1 MB, gera o pôster e põe no catálogo.

DesignPublica

Põe o planeta no ar (e na S3, se a engenharia usar, automaticamente) e avisa o id novo.

EngenhariaUsa o id

<Planeta id="planeta-<nome>" />, e pronto.

Perguntas frequentes

Usamos a pasta src/

Mova para src/components/planetas. Se o alias apontar para src/, o import @/components/planetas não muda.

Id que não existe

Fica só o espaço do planeta, e o console avisa com a lista dos ids publicados.

Onde os arquivos ficam

Em planetas-3d.vercel.app, e o kit funciona assim, sem configurar nada. Usar a S3 da JG é opcional e recomendado para produção (página 6).

Política de segurança (CSP)

Libere o endereço dos planetas (a CDN) em img-src e connect-src, e inclua 'wasm-unsafe-eval' em script-src (a malha usa WebAssembly).

Muitos planetas na mesma tela

Cada planeta 3D usa um contexto WebGL, e os navegadores aceitam ~16. Em listas longas, mostre o pôster como imagem e use o 3D só no destaque.

SSR

O servidor entrega o pôster em HTML comum, e o navegador troca pelo 3D. Não há layout shift: o tamanho é fixo pela prop.

Peso

Menos de 1 MB por planeta (~0,8 MB), baixado só quando ele aparece na tela, mais ~250 KB do decodificador da malha, uma vez só. O pôster tem ~80 KB. Sem rede ou sem WebGL, fica o pôster.

Versões testadas

Next.js 15.5, React 19.1 e three 0.170 (a única dependência). Também funciona com Next 13+ e React 18+.

Produção na S3 · opcional

Os planetas na S3 da Jovens Gênios

✓ Sem a S3, já funciona

Sem configurar nada, o kit usa os planetas publicados em planetas-3d.vercel.app, do mesmo jeito e com os mesmos ids. Planeta novo continua sendo só o id novo. Esse endereço está numa conta pessoal da Vercel, no plano gratuito: bom para testes e piloto.

Para produção com alunos

Recomendado: copiar os arquivos para a S3 da Jovens Gênios (passos abaixo) ou transferir o projeto planetas-3d da Vercel para uma conta paga da JG, mantendo o mesmo endereço. Nos dois casos, o componente e o uso pelo id não mudam.

1

Bucket e CDN

Bucket privado com CloudFront (acesso por OAC). No comportamento da distribuição, use a política de cache CachingOptimized e a de cabeçalhos de resposta SimpleCORS (os planetas são lidos por outros domínios). Se servir direto da S3, sem CDN, aplique o CORS do repositório:

aws s3api put-bucket-cors --bucket <bucket> \
  --cors-configuration file://ferramentas/s3/cors.json
2

Primeira carga

Com o AWS CLI configurado. Copia public/planetas e public/draco para <bucket>/<pasta>/ (~15 MB), com o tipo e o cache certos de cada arquivo (tabela na página 7), e envia o catálogo por último. SECO=1 só mostra o que faria.

git clone https://github.com/Jovens-Genios/Planetas-3D && cd Planetas-3D
BUCKET=<bucket> PREFIXO=exploradores CLOUDFRONT_ID=<id> \
  bash ferramentas/s3/publicar_s3.sh
3

Conferir

Testa todos os arquivos de todos os planetas pelo endereço público: resposta 200, tipo, CORS e tamanho.

node ferramentas/s3/verificar.mjs https://<cdn>/exploradores/
# … Tudo certo: 14 planetas. Use NEXT_PUBLIC_PLANETAS_URL=https://<cdn>/exploradores/
4

Apontar os projetos

Em cada projeto que usa o kit (ou nas variáveis do deploy). É lida no build: refaça o deploy depois de mudar. Libere a CDN na CSP (página 5).

# .env.production
NEXT_PUBLIC_PLANETAS_URL=https://<cdn>/exploradores/

Produção na S3 · planeta novo automático

Planeta novo sobe sozinho para a S3

O repositório já tem o envio automático (.github/workflows/publicar-s3.yml). Ele fica desligado até a engenharia preencher as variáveis. Depois disso, quando o Design publica um planeta no repositório, ele chega à S3 em ~1 minuto, sem ninguém da engenharia.

5

Ligar o envio automático

No GitHub: Jovens-Genios/Planetas-3D → Settings → Secrets and variables → Actions.

S3_BUCKET nome do bucket (liga o envio)
AWS_REGION região do bucket
S3_PREFIXO a pasta (ex.: exploradores)
CLOUDFRONT_ID a distribuição, para limpar o cache
PLANETAS_URL endereço público, conferido no fim
AWS_ROLE_ARN papel IAM com acesso por OIDC (recomendado)

Sem OIDC, use os secrets AWS_ACCESS_KEY_ID e AWS_SECRET_ACCESS_KEY. Permissões necessárias: s3:ListBucket e s3:PutObject no bucket, e cloudfront:CreateInvalidation na distribuição. Para testar, rode o workflow manualmente na aba Actions.
